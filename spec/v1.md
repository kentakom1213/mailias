# mailias protocol v1

## Address format

```text
<label>-v1-<tag>@<domain>
```

`label` is canonicalized to lowercase ASCII and must match
`[a-z0-9]+(-[a-z0-9]+)*`. Its maximum length is 48 bytes.

`domain` is a lowercase ASCII DNS name without a trailing dot.

## Secret key

The secret key is exactly 32 bytes. Its external representation is unpadded
Base64URL as defined by RFC 4648.

## HMAC input

The tag is derived using HMAC-SHA-256. The message is the following byte
sequence, where each text component is encoded as ASCII:

```text
"mailias/v1" || 0x00 || domain || 0x00 || label
```

The forwarding destination is deliberately not part of the HMAC input.

## Tag encoding

Take the first five bytes of the HMAC output and split the resulting 40-bit
big-endian value into eight 5-bit values, most significant group first. Map
each value to this 32-character alphabet:

```text
023456789abcdefghjkmnpqrstuvwxyz
```

Verification compares the eight tag bytes without an early exit. Unknown
protocol versions and malformed recipients are invalid.

## Recipient handling

For verification, the recipient local part and domain are canonicalized to
lowercase ASCII. The local part is parsed from the right so that `v1` may also
appear inside the label.

Invalid recipients are silently dropped by the Email Worker. Configuration,
secret-loading, and cryptographic failures also fail closed.
